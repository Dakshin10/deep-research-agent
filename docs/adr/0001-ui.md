# ADR 0001: Frontend Architecture & Custom Next.js Application Selection

**Status**: Accepted  
**Date**: 2026-10-26  
**Deciders**: Principal Engineering Team  
**Scope**: User interface architecture, evaluation of open-source frameworks (LibreChat, Open WebUI) vs bespoke Next.js implementation.

---

## 1. Context & Problem Statement

Our goal is a Claude-style, unified single-turn AI assistant product with deep integration into:
- Typed SSE streaming protocol (`docs/chat-protocol.md`).
- Live inline research progress cards (real-time shard status, sources by family, budget meter).
- Exact document location citation chips with hovercards and Scroll-to-Text (`#:~:text=`) deep links.
- Collapsible Code Mode execution cards displaying agent-written JavaScript and sandboxed results.
- Versioned Artifacts drawer in a collapsible right panel (markdown reports, CSV tables, PPTX decks, IdeaCards).
- Interactive temporal Memory Graph view with bidirectional Obsidian vault synchronization.
- Human-in-the-loop mutation approval cards and clarification reply chips.

We must evaluate whether to fork an existing open-source chat framework (**LibreChat**, **Open WebUI**) or build a **custom Next.js (App Router) + TypeScript + Tailwind + shadcn/ui** frontend.

---

## 2. Options Considered

### Option A: Forking LibreChat
- **Overview**: An open-source, feature-rich multi-model chat UI with plugin/agent support and user authentication.
- **Pros**: Established user management, conversation search, preset sharing.
- **Cons**:
  - Heavily opinionated MERN-stack architecture (MongoDB/Express backend) that duplicates our Python FastAPI/Postgres backend.
  - Complex custom SSE event model: injecting custom events (`research_progress`, `code_execution`, `memory_used`, exact citation text-fragment links) requires rewriting large portions of LibreChat's message pipeline.
  - No native support for a right-hand versioned artifact drawer or interactive temporal graph memory inspector.
  - High maintenance overhead maintaining a divergent fork.

### Option B: Forking Open WebUI
- **Overview**: A popular self-hosted web UI designed primarily for Ollama and OpenAI-compatible endpoints.
- **Pros**: Svelte-based, clean UI, integrated RAG tools.
- **Cons**:
  - Built on Svelte/Python with an internal database that conflicts with our FastAPI/Postgres multi-tenancy RLS model.
  - Tight coupling to standard OpenAI chunk streaming (`choices[0].delta.content`), making it difficult to cleanly stream complex custom events like multi-shard latency rows, interactive approval cards, and text-fragment citation drawers.
  - Fork maintenance is onerous and hard to keep synchronized with upstream releases.

### Option C: Custom Next.js 14+ (App Router) with Tailwind + shadcn/ui (Selected)
- **Overview**: Modern bespoke web application built with Next.js App Router, TypeScript, TailwindCSS, and shadcn/ui primitives, using custom SSE adapters.
- **Pros**:
  - **100% Protocol Alignment**: First-class support for our typed SSE protocol (`docs/chat-protocol.md`). Every event (`research_progress`, `code_execution`, `citation`, `artifact`, `approval_request`) maps directly to dedicated React components.
  - **Artifacts & Memory UX**: Clean three-pane layout (Left Navigation Sidebar, Center Chat, Right Collapsible Artifacts/Sources Drawer) and interactive graph view without framework impedance.
  - **Performance & Aesthetics**: Dark/light theme matching modern high-end minimalist design standards, zero extraneous dependencies, full control over keyboard shortcuts and file dropzones.
  - **Monorepo Simplicity**: Plugs directly into `apps/web/`, communicating with `apps/api/` over `/v1/chat`.

---

## 3. Decision

We choose **Option C: Custom Next.js (App Router) with TypeScript, TailwindCSS, and shadcn/ui**.

Key implementation principles:
1. Custom SSE Stream Adapter (`useChatStream`) consuming `POST /v1/chat` and parsing typed JSON events.
2. Layout:
   - Left Sidebar: Conversations, search, new chat, memory graph link.
   - Center Chat: Markdown message streaming, syntax-highlighted code with copy, collapsible tool calls, live research cards, inline clarification pills, mutation approval cards.
   - Right Drawer: Artifact viewer (markdown report download, idea cards table) and verified sources drawer.
3. Retire legacy `app.py` prototype to `legacy/app.py`.
